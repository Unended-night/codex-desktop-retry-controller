## 后续版本的预期

当前拆分函数规则通过行为与结构关系识别，已去掉内部函数名、遥测名称、日志及错误提示文字作为定位条件；历史精确家族规则仍保留原有约束。没有可据此计算的未来版本兼容率，也不保证所有更新后直接复用。

本轮在真实 `0.163.0-alpha.10.2` 字节上，将四类日志、遥测和错误提示共 17 处等长改写，仍得到相同结构结果及六处补丁计划；变造内容仅在内存中分析，没有执行。单元夹具另覆盖枚举编号/立即数宽度变化、零至四层包装、字段/寄存器漂移，以及不成立关系的拒绝，不能把合成变化当作尚未发布的真实版本已通过。

| 上游变化 | 当前规则的预期与边界 |
|---|---|
| 内部函数重命名、日志/遥测文字调整 | 新规则不依赖这些名称，纯文字变化不应单独导致失效 |
| 文件地址或状态字段移动、部分寄存器重分配 | 从 PE 和指令操作数推导；数据流、字段及分支关系仍成立时可复用 |
| 错误枚举编号、原生终止位图变化 | 读取当前分类器并保留原版判定；HTTP 范围常数从操作数读取，不追加版本位图白名单 |
| HTTP helper 增减包装函数 | 最多四层、有限直接调用图；所有已识别调用者均须通过范围检查 |
| 同时保留多个 Responses HTTP 实现 | 收集全部通过范围证明的 SSE 预算门；有无法证明的候选则拒绝，不能只按名称选一个 |
| ABI、Duration 表示、指令调度或控制流大改 | 仍可能需要更新规则；例如端点的指针/长度存储方式改变、改成间接调用或改变外层重试职责 |
| WebSocket、其他平台或未测试 feature 组合 | 不在现有完整验收保证内，不能从 HTTP 默认路径通过推导全部兼容 |

官方更新后，自定义入口会沿用保存参数，重新识别并验收新副本，全部通过才切换。识别失败或行为不符时保留参数和原指针，本次回退官方；规则修复后可重新验证。这里复用的是控制器与参数，新构建仍需制作和验收对应副本，不能直接沿用旧二进制补丁或旧批准。

## 平台和安装方式

- 支持目标是 Windows x64 官方 Codex 桌面包，定位当前用户注册的 `OpenAI.Codex` 包，并读取其中的桌面程序和 resources。
- Python 3.10+ 64 位及 tkinter 是运行要求；本轮 Windows x64 / Python 3.10.14 下，工作目录与仅含公开源码的独立依赖环境均通过 132 项单元测试。其他 Python 版本未在本轮逐一验证。
- 首次公开整理的 Windows venv 全量回归曾出现一项进程恢复断言失败，随后该组 17 项单独复跑通过。当时直接解释器配合独立依赖目录通过 107 项，上一轮适配通过 122 项，本轮加固通过 132 项；独立依赖目录运行不等于 venv 进程环境已完整验收，该限制仍保留。
- 不支持直接套用于 macOS、Linux、WSL、Windows ARM64 或独立安装的终端 CLI。
- 不将某个 Windows 最低版本列为已经验证的保证；需要能正常运行官方桌面版并具备代码使用的 Windows Shell、Job Object、受限令牌等系统接口。
- 部分早期 `tests/verify_*.py` 使用旧版 `%LOCALAPPDATA%/OpenAI/Codex/bin` 定位方式，不能视为当前桌面包的一键验证入口。主控制器和启动器使用注册表定位。

## 重试行为边界

完整套件覆盖 HTTP 429 / 500 / 529、流中断、连接错误、Retry-After、服务端等待建议、失败后恢复、app-server、1000 次预算和撤销恢复；新版套件另对照原版 HTTP 400 / 401 / 403 / 404 的分类行为。

当前构建静态识别到两个 Responses SSE HTTP 预算门，均按同一策略生成补丁；调用范围通过直接调用图检查。行为套件使用临时配置的 HTTP 默认路径，没有逐一切换上游所有 feature 组合，也未分别证明每个预算门都被动态执行，不能据此扩大保证范围。

普通 429 可进入有限预算；明确的 `insufficient_quota` 仍终止。补丁保留原构建对其他错误的分类，例如旧 `0.160.0` 原版对普通 401 / 403 也可能进行外层重试。

固定间隔从失败处理后计时。0 秒表示不额外主动等待，实际网络、进程调度和请求仍有耗时。最大重试次数不包含首次请求；设置 N 次通常对应最多 N+1 次尝试。

## 沙盒、配置与传输

桌面副本发布包含原版/副本共六个 Windows **unelevated** 临时命令场景，比较工作区内外写入、read-only、受限令牌和联网/离线代理策略。网络项验证代理及环境限制；直接回环 TCP 可连接，不能据此声称具有不可绕过的防火墙隔离，也不能推导 elevated/注册服务模式已等价验证。

真实配置由 Codex 自行读取。切换供应商、模型、地址、权限、profile、注释或 CODEX_HOME 不单独触发副本回退，配置缺失或无效也不由控制器偷偷修正。覆盖范围提示不代表对应组合已实测。WebSocket、远程主机、所有后台请求以及其他权限/网络组合尚未完整验收。

## 如何确认本机状态

```powershell
python -B -X utf8 desktop_runtime.py status
python -B -X utf8 desktop_trial.py --check
```

检查界面的“当前运行”与“下次启动”，避免把已保存参数当作当前进程正在使用的参数。结构识别通过、单元测试通过、完整行为批准、桌面实际选中副本是不同层次，必须分别确认。

新构建不兼容时先使用官方入口；保留保存参数即可。规则更新后执行 `git pull`，再通过控制器重新验证，或在已启用自定义入口的下次启动中触发适配。不对任意未来内部重构承诺自动兼容。
