## 平台和安装方式

- 支持目标是 Windows x64 官方 Codex 桌面包，定位当前用户注册的 `OpenAI.Codex` 包，并读取其中的桌面程序和 resources。
- Python 3.10+ 64 位及 tkinter 是运行要求；本轮 Windows x64 / Python 3.10.14 下，工作目录与仅含公开源码的独立依赖环境均通过 122 项单元测试。其他 Python 版本未在本轮逐一验证。
- 首次公开整理的 Windows venv 全量回归曾出现一项进程恢复断言失败，随后该组 17 项单独复跑通过。当时直接解释器配合独立依赖目录通过 107 项，本次适配后通过 122 项；独立依赖目录运行不等于 venv 进程环境已完整验收，该限制仍保留。
- 不支持直接套用于 macOS、Linux、WSL、Windows ARM64 或独立安装的终端 CLI。
- 不将某个 Windows 最低版本列为已经验证的保证；需要能正常运行官方桌面版并具备代码使用的 Windows Shell、Job Object、受限令牌等系统接口。
- 部分早期 `tests/verify_*.py` 使用旧版 `%LOCALAPPDATA%/OpenAI/Codex/bin` 定位方式，不能视为当前桌面包的一键验证入口。主控制器和启动器使用注册表定位。

## 重试行为边界

完整套件覆盖 HTTP 429 / 500 / 529、流中断、连接错误、Retry-After、服务端等待建议、失败后恢复、app-server、1000 次预算和撤销恢复；新版套件另对照原版 HTTP 400 / 401 / 403 / 404 的分类行为。

普通 429 可进入有限预算；明确的 `insufficient_quota` 仍终止。补丁保留原构建对其他错误的分类，例如旧 `0.160.0` 原版对普通 401 / 403 也可能进行外层重试。

固定间隔从失败处理后计时。0 秒表示不额外主动等待，实际网络、进程调度和请求仍有耗时。最大重试次数不包含首次请求；设置 N 次通常对应最多 N+1 次尝试。

## 沙盒、配置与传输

桌面副本发布包含原版/副本共六个 Windows **unelevated** 临时命令场景，比较工作区内外写入、read-only、受限令牌和联网/离线代理策略。网络项验证代理及环境限制；直接回环 TCP 可连接，不能据此声称具有不可绕过的防火墙隔离，也不能推导 elevated/注册服务模式已等价验证。

真实配置由 Codex 自行读取。切换供应商、模型、地址、权限、profile、注释或 CODEX_HOME 不单独触发副本回退，配置缺失或无效也不由控制器偷偷修正。覆盖范围提示不代表对应组合已实测。WebSocket、远程主机、所有后台请求以及其他权限/网络组合尚未完整验收。

## 如何确认本机状态

```powershell
python -B -X utf8 desktop_runtime.py status
python -B -X utf8 desktop_trial.py --check
```

检查界面的“当前运行”与“下次启动”，避免把已保存参数当作当前进程正在使用的参数。结构识别通过、单元测试通过、完整行为批准、桌面实际选中副本是不同层次，必须分别确认。

新构建不兼容时先使用官方入口；保留保存参数即可。规则更新后执行 `git pull`，再通过控制器重新验证，或在已启用自定义入口的下次启动中触发适配。不对任意未来内部重构承诺自动兼容。
