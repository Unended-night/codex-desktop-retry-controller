## 此前 HTTP 状态来源修复记录

本次失配是 HTTP 状态指针先位于 RAX，分类过程复用该寄存器，之后从同一栈槽恢复到 RDI。旧规则要求状态始终位于同一非易失寄存器，因此漏掉实际使用的内层预算门，零预算仍发出五次请求，行为验收正确拦截了发布。规则现在证明完整寄存器复制或同一未改写栈槽的恢复关系，保留计数器存活、字段不重叠和分支检查；两个 Responses HTTP 门均进入补丁计划，零预算恢复为一次请求。未添加固定版本、地址、栈偏移或寄存器组合白名单。原有 Duration、错误指针和分类规则继续保留，边界见[原理说明](ARCHITECTURE.md)。

本轮完整发布约 6 分 29 秒，包含结构分析、18 项原生场景、恢复原始摘要、重复恢复、部分写入恢复、拒绝覆盖无关修改、实际参数及沙盒验收；未放宽 20 分钟总时限。官方组件与原指针指向的旧副本摘要保持不变。该次发布的附加完整性脚本发现真实配置摘要变化，不能将其记为“全部受保护文件未改变”；代码检查显示发布链路只读真实配置，模型及沙盒测试使用临时配置，原始异常记录保留。正常退出后从自定义入口启动，才能确认桌面实际使用新副本。

后续在隔离管理目录重新执行 `pythonw → worker` 发布与恢复集成验收，2 次 / 250 ms 参数、六项沙盒对照及七种配置变化检查均通过；真实配置、官方引擎、已选副本和真实启动指针四项摘要全部保持不变，未复现配置完整性异常。此前那次配置变化的来源未确定，也未回滚用户配置。只读状态复核为 `compatible=true`、`verified=true`、下次 `custom-trial` 50 次 / 1 秒，当前仍运行官方引擎。

## 后续版本的预期

当前拆分函数规则通过行为与结构关系识别，已去掉内部函数名、遥测名称、日志及错误提示文字作为定位条件；历史精确家族规则仍保留原有约束。没有可据此计算的未来版本兼容率，也不保证所有更新后直接复用。

上一轮在真实 `0.164.0-alpha.11.1` 字节上，将日志、遥测和错误提示共 19 处等长改写，仍得到相同结构结果及六处补丁计划；变造内容仅在内存中分析，没有执行。本轮单元夹具增加同一栈槽恢复、完整寄存器复制及无效来源的拒绝，同时保留空值编码、分支、有符号分类、枚举变化、包装层数和字段漂移回归。合成变化不能当作尚未发布的真实版本已通过。

| 上游变化 | 当前规则的预期与边界 |
|---|---|
| 内部函数重命名、日志/遥测文字调整 | 新规则不依赖这些名称，纯文字变化不应单独导致失效 |
| 文件地址或状态字段移动、部分寄存器重分配 | 从 PE 和指令操作数推导；数据流、字段及分支关系仍成立时可复用 |
| 错误枚举编号、原生终止位图变化 | 读取当前分类器并保留原版判定；HTTP 范围常数从操作数读取，不追加版本位图白名单 |
| Duration 空值编码、相等分支方向和有限块重排 | 核对调用方与分类器的编码，保留清理块；从同一错误栈槽推导所需的指针加载，关系不成立仍拒绝 |
| HTTP 有符号/无符号条件移动 | 保留当前分类指令，校验状态字段、标志来源和后续分支关系 |
| HTTP 状态寄存器被复用，随后复制或从栈槽恢复 | 追踪完整寄存器复制或同一未改写的 RBP/RSP 栈槽；跨调用丢失、栈写入或分支绕过恢复时拒绝 |
| HTTP helper 增减包装函数 | 最多四层、有限直接调用图；所有已识别调用者均须通过范围检查 |
| 同时保留多个 Responses HTTP 实现 | 收集全部通过结构和范围证明的 SSE 预算门；结构成立但调用范围无法证明时拒绝，结构未识别的路径仍可能遗漏，须由行为验收检出 |
| ABI、Duration 表示、指令调度或控制流大改 | 仍可能需要更新规则；例如端点的指针/长度存储方式改变、改成间接调用或改变外层重试职责 |
| WebSocket、其他平台或未测试 feature 组合 | 不在现有完整验收保证内，不能从 HTTP 默认路径通过推导全部兼容 |

官方更新后，自定义入口会沿用保存参数，重新识别并验收新副本，全部通过才切换。识别失败或行为不符时保留参数和原指针，本次回退官方；规则修复后可重新验证。这里复用的是控制器与参数，新构建仍需制作和验收对应副本，不能直接沿用旧二进制补丁或旧批准。

## 平台和安装方式

- 支持目标是 Windows x64 官方 Codex 桌面包，定位当前用户注册的 `OpenAI.Codex` 包，并读取其中的桌面程序和 resources。
- Python 3.10+ 64 位及 tkinter 是运行要求；本轮 Windows x64 / Python 3.10.14 工作目录通过 152 项单元测试，约 16 秒，另通过 Tk 界面冒烟检查。此前仅含公开源码的独立依赖环境通过当时的 136 项，本轮未重跑该独立环境或其他 Python 版本。
- 上一轮清理入口测试曾因父进程 mock 未传入子进程而读取真实进程列表失败；已让该测试在当前进程运行实际 worker 入口，正式进程保护检查保持原样。首次公开整理的 Windows venv 全量回归另曾出现一项进程恢复断言失败，随后该组 17 项单独复跑通过；独立依赖目录运行不等于 venv 进程环境已完整验收，该历史限制仍保留。
- 不支持直接套用于 macOS、Linux、WSL、Windows ARM64 或独立安装的终端 CLI。
- 不将某个 Windows 最低版本列为已经验证的保证；需要能正常运行官方桌面版并具备代码使用的 Windows Shell、Job Object、受限令牌等系统接口。
- 部分早期 `tests/verify_*.py` 使用旧版 `%LOCALAPPDATA%/OpenAI/Codex/bin` 定位方式，不能视为当前桌面包的一键验证入口。主控制器和启动器使用注册表定位。

## 重试行为边界

完整套件覆盖 HTTP 429 / 500 / 529、流中断、连接错误、Retry-After、服务端等待建议、失败后恢复、app-server、1000 次预算和撤销恢复；另对照原版 HTTP 400 / 401 / 403 / 404 的分类行为，并验证 1 ms 固定等待，以及 100 ± 70、1000 ± 70、5 ± 4 ms 随机等待。

当前构建静态识别到两个 Responses SSE HTTP 预算门，均按同一策略生成补丁；调用范围通过直接调用图检查。行为套件使用临时配置的 HTTP 默认路径，没有逐一切换上游所有 feature 组合，也未分别证明每个预算门都被动态执行，不能据此扩大保证范围。

普通 429 可进入有限预算；明确的 `insufficient_quota` 仍终止。补丁保留原构建对其他错误的分类，例如旧 `0.160.0` 原版对普通 401 / 403 也可能进行外层重试。

固定或随机等待从失败处理后计时，请求自身耗时另计，不对成功请求限速。1 ms 是参数精度；Windows 调度不保证准时发起请求，5 ± 4 ms 场景实测请求间隔约 15～32 ms。0 秒表示不额外主动等待。基础等待及扰动以整数毫秒表示，整个取值范围必须在 0～60000 ms 内；扰动为 0 保持原固定等待。最大重试次数不包含首次请求；设置 N 次通常对应最多 N+1 次尝试。

探测使用临时配置关闭插件功能，避免每个全新 CODEX_HOME 同步插件目录带来的联网延迟；不改动用户真实插件配置。本轮动态保证仍限于这些临时配置覆盖的重试路径，不据此推导所有插件或 feature 组合。

## 沙盒、配置与传输

桌面副本发布包含原版/副本共六个 Windows **unelevated** 临时命令场景，比较工作区内外写入、read-only、受限令牌和联网/离线代理策略。网络项验证代理及环境限制；直接回环 TCP 可连接，不能据此声称具有不可绕过的防火墙隔离，也不能推导 elevated/注册服务模式已等价验证。

真实配置由 Codex 自行读取。切换供应商、模型、地址、权限、profile、注释或 CODEX_HOME 不单独触发副本回退，配置缺失或无效也不由控制器偷偷修正。覆盖范围提示不代表对应组合已实测。WebSocket、远程主机、所有后台请求以及其他权限/网络组合尚未完整验收。

## 如何确认本机状态

```powershell
python -B -X utf8 desktop_runtime.py status
python -B -X utf8 desktop_trial.py --check
```

检查界面的“当前运行”与“下次启动”，避免把已保存参数当作当前进程正在使用的参数。结构识别通过、单元测试通过、完整行为批准、桌面实际选中副本是不同层次，必须分别确认。

新构建不兼容时先使用官方入口；保留保存参数即可。规则更新后执行 `git pull`，再通过控制器重新验证，或在已启用自定义入口的下次启动中触发适配。不对任意未来内部重构承诺自动兼容。
