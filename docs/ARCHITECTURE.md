# 工作原理与边界

> 本分支是 2026-11-22 的失败尝试归档。HTTP 超时入口在实际桌面使用中失败，已停止采用；以下保留当时设计，最终结论见[失败记录](FAILED-ATTEMPT-2026-11-22.md)。

## 独立副本和启动选择

控制器不直接覆写官方安装。它从当前用户注册的 Codex 桌面包中读取引擎和同版本配套组件，在 `runtime/` 下创建新一代副本；重试补丁和 HTTP 超时分别开关与验收，通过后才更新 `state/desktop-trial.json`。只开超时时保留官方引擎的完整原始字节，不应用重试补丁。

```mermaid
flowchart TD
    A[自定义启动入口] --> B[定位当前官方构建]
    B --> C{已选副本和验收收据有效?}
    C -->|所选功能全部有效| D[启动桌面并选择可用入口]
    C -->|缺失功能且已启用自定义| E[沿用保存参数，分别验收]
    E -->|全部或部分通过| F[发布可用功能，缺失项提示待适配]
    F --> D
    E -->|全部失败| G[保留参数及原指针，无有效副本则用官方]
    E -->|冷却中| D
    C -->|官方默认或尚未设置| G
```

正式启动前还会重新检查进程与构建。桌面已运行时不会终止它来切换引擎；用户需要正常退出后重启。副本通过进程级 `CODEX_CLI_PATH` 提供给桌面，原环境和真实配置由 Codex 自行加载。官方入口独立保留。

## 重试补丁

`controller/native*.py` 使用 PE 结构和 x64 指令分析识别模型 HTTP/Responses/SSE 采样路径。新规则优先匹配字段关系、函数边界和分支控制流，而不是只匹配某个版本号或固定偏移。

### 分离 kind / Duration 的规则

`native_delegate.py` 支持错误种类分类与 Duration 策略分离的形态：从策略的 kind 区间、共同错误对象、服务器期限字段、空值返回和被调用的字节标签表推导关系，保留两个原生函数。采样预算还核对存入帧槽的字段指针、同一状态来源、报告参数，以及跨过连接分支时必须重放的非易失错误指针加载。

短 `cmp edx,-1` 不足以容纳 CALL 时，将完整比较与条件分支改为 JMP，叶代码直接跳回原有有效／空值出口，不新增调用栈。压缩分类调用后允许保留不破坏返回值和错误指针的帧加载；已有已定位循环如果证明失败，会拒绝整个适配，不能静默漏补。0.171 构建由此识别到四处采样、三处 HTTP 预算和三处压缩；这不是固定数量白名单。

### 原生返回值规则（0.169 构建已验证）

新版错误对象改用字节标签和跳转表，压缩也开始调用采样所用的原生错误分类器。`native_return.py` 从原生入口、返回空值、跳转表和 Debug 格式化流程推导标签位置与 String 字段；不从历史位图猜测新枚举编号。错误对象指针必须在分派后保持有效，采样和压缩调用者的 None 编码必须与分类器一致。

这一路径保留原生分类函数的全部指令、调用和异常展开记录，只把调用之后的 Duration 比较替换成一个叶辅助函数调用。辅助函数重新加载已证明的错误指针，在有效 Duration 上设置用户等待；明确终止继续返回 None。原生少数分支仅在缺少服务器截止时间时返回 None，这些分支通过“Duration 字段加载、空值比较、终止边、成对保存”的关系识别，改用用户等待，不写死错误编号。普通 429 在当前构建属于该结构，明确额度耗尽不属于。特殊 400 仍由同一枚举的 InvalidRequest Debug 名称、String 指针/长度和精准 JSON 字段匹配限制。

辅助函数不分配栈或修改非易失寄存器；按已证明的 RBP 栈槽或非易失寄存器读取错误指针。返回前重新比较 Duration 空值，使原有 JE/JNE 同时获得正确返回值和标志。保护页测试实际执行该辅助函数，检查非法指针、文本截断和 ZF。引擎本体只在临时副本中执行完整行为验收。

采样中的服务器截止时间使用整对加载范围替换，因此支持两个较短的 disp8 指令；被忽略的秒值随 None 纳秒标记一起成为无效截止时间。原有成对保存不变，外部分支不得进入替换范围内部。状态从同一帧槽恢复到另一寄存器时，预算跳转包含这条恢复指令；返回值规则允许易失状态寄存器，因为赋预算的辅助代码通过 JMP 执行并保持该寄存器。

新版压缩规则核对预算初始化、同一状态来源、错误对象复制位置、计数增量、分类器参数、成对 Duration 保存以及预算耗尽分支，统一设置预算和等待，同时忽略服务器截止时间。旧的直接退避调用结构继续使用旧规则。三处采样、两处 HTTP 和两处压缩的默认行为已通过验收，不代表逐一强制运行过所有编译实例或 feature 组合。

### 旧分类前缀与共享结构规则

对拆分函数后的实现，分类器追踪错误标签、寄存器别名、符号标志与原生终止位图的关系，沿用原构建的错误分类；HTTP 预算门则从指令推导计数器、状态字段和预算，核对字段不重叠、寄存器存活、分支边界及递增保存关系。枚举编号、寄存器分配和字段位置允许在这些关系成立时变化。

采样状态也可能在其他函数中构造，再传入重试循环。没有局部预算初始化的结构会额外核对预算、计数、Duration 字段互不重叠，错误参数来自同一栈槽，多个实例共享同一分类器和重试通知函数。通过后收集这些实例，在各自原预算比较前写入用户预算。重定向只替换连接路径入口的一条完整指令，预算赋值放在副本新增节内；中间的恢复块与跳转表目标保持原样。已经支持的局部初始化结构继续使用原规则。

Duration 保存和预算比较之间允许插入一条已证明的字段取址指令：来源必须是相同状态的计数或预算字段，目标是独立的非易失寄存器；指令保留在原位置执行。未证明的地址、寄存器破坏或分支进入补丁内部仍拒绝适配。这覆盖有限的编译器调度变化，不是跳过任意插入指令。

错误 Debug 分派从函数入口追踪原始标签、对象指针和 niche 常量，允许寄存器重分配，以及特殊错误分支之后才加载归一化常量。名称可以与其他可打印文本相邻，仍核对精确名称长度、枚举跳转表和 String 格式化字段。压缩计数器取址前也允许从同一栈槽重新加载状态到另一个寄存器；错槽或寄存器别名破坏仍会被拒绝。

新增的两类可恢复错误只扩展原生 `InvalidRequest` 分支。规则通过该枚举的 Debug 分发表和 `&String` 格式化器推导标签、文本指针及长度，再与采样分类器交叉检查；不写死枚举编号或 String 字段偏移。生成的辅助代码在 String 边界内匹配 JSON 的 `code` 完整值 `invalid_encrypted_content`，或 `message` 开头完整的资源不匹配说明（允许后接 trace 信息）。资源说明分为可选的已观察前缀 `OpenAI Responses bad request: `、固定原因、`Azure` 或 `***`、固定修复说明；字面量比较全部成功后才推进游标，省略前缀或切换名称时不会丢失位置。未知前缀、相似但不完整的说明、普通 `bad response`、其他 code、把 code 写进 message 的情况均不因此放开。它仍受现有外层预算限制。

错误名称引用按已要求的 `LEA RDX,[RIP+rel32]` 参数指令一次扫描所有执行节，同时匹配全部候选名称地址；避免每个名称重复进行通用全文件引用搜索。操作数内重叠、跨扫描块的候选仍保留，执行节末尾截断指令排除，之后的完整解码、分发表和字段关系检查不变。恢复时使用原始长度的内存视图核对完整摘要，变更撤销范围时仅对追加区补零，避免复制整份引擎来补几个字节；返回值仍是完整恢复后的不可变字节。

本地压缩有独立的默认预算和退避调用。规则从原生分类器的退避目标找到候选，检查预算初始化、计数器增量、同一异步状态来源、Duration 的成对保存及退出分支。当前构建识别到两份实现，均修改为用户配置；压缩中缩减历史的诊断文字仅作额外范围锚点。两份实现保留原有错误处理和历史缩减逻辑。独立远程压缩的另一份内联重试实现尚未适配，不据此声称所有压缩传输路径都受控。

精准错误判断需要更多指令空间，因此在独立副本尾部添加 `.cretry` 只读可执行节，修改经过校验的空闲节头、节数和大小字段；已有节权限及异常表保持原样。辅助函数只使用易失寄存器，不调用外部函数、不操作栈，通过相对 CALL 返回原流程。压缩使用同一等待生成器。格式 2 撤销记录同时保存原始长度与扩充长度，允许追加被中断时恢复，恢复后截回原长度并核对完整原始 SHA；格式 1 和旧补丁范围仍可撤销。

HTTP 状态对象可以通过完整的 64 位寄存器复制，或从同一未被改写的 RBP/RSP 栈槽恢复到另一寄存器。分类指令可以复用先前的状态寄存器，最终写回仍须指向已证明的同一对象，计数器仍须跨调用存活。这个有限顺序片段检查会跟踪子寄存器破坏、重叠栈写入、栈基址变化与地址逸出；调用会清除易失寄存器，并使 RSP 调用暂存区中的来源失效。分支若可能绕过必要恢复则拒绝。`0.165` 的旧规则只识别出另一条 HTTP 路径，零预算仍发出五次请求；完整行为验收因此拦截发布。状态来源证明修复后，两条路径都被识别，零预算恢复为一次请求。

`Option<Duration>` 的无等待标记从调用方的比较操作数推导，并独立核对分类器确实返回同一个值；不把十亿纳秒的数值边界当作所有构建的空值编码。支持相等与不相等分支的两种布局，分别追踪有效时长和错误清理路径。清理块即使被排到连接判断与预算块之间，也保留其原始字节，不作为补丁空间。HTTP 错误归一化允许原生有符号或无符号条件移动，仍核对标志来源和字段关系；补丁不改写这些分类指令。

连接特例被跳过时，预算路径仍需要原来的错误指针。若编译器把该指针的 R8 栈加载移入连接块，而预算路径在调用前没有重新写入 R8，规则核对它与分类器 RCX 参数来自同一栈槽，并检查通向预算块的分支及寄存器别名破坏。通过后在跳转前重放这条原生加载；栈偏移从当前指令推导。`0.164` 的首轮行为验收发现缺失该加载会造成访问违规，因此不能仅凭结构识别通过就发布。

原有采样和 HTTP 拆分函数规则不使用内部函数名、遥测名、日志或错误提示文字定位；新增错误布局和压缩规则的语义锚点见上文。独立 HTTP helper 必须能沿已解码直接调用追溯到 Responses 请求构造函数；端点须以指针和正确字节长度写入同一对象的相邻字段，单纯出现 `/responses` 文字不足以通过。允许最多四层包装，并核对包装链与共同模型调用者的连通关系；遍历最多 64 次，未知调用者、循环、超深、尾跳转、取函数地址或原始函数指针均拒绝。这个有限调用链检查不能证明所有动态间接调用路径。

同一构建可能同时保留多个 Responses HTTP 实现。当前规则收集全部通过结构与调用范围检查的 SSE 预算门，统一取消内部预算叠加；不按某个遥测名称优先选择一处。发现结构成立却无法证明调用范围的候选时，拒绝整个适配。是否改变预期请求次数、错误分类或恢复行为，仍由真实引擎验收判断；验收配置未覆盖的所有 feature 组合不能据此视为已验证。

旧精确家族规则继续保留，以兼容历史构建及撤销记录；其中仍存在固定指令、枚举或日志标记要求，不能把当前拆分函数规则的适应能力推广到全部旧规则。

相同原始字节的成功结构分析在当前进程内复用，以避免验收期间反复扫描整个引擎。每次调用仍计算完整 SHA-256，文件变化会重新分析，失败结果不缓存；跨分析只保留一份小型结构结果并向调用者返回独立副本，不保留可执行文件或反汇编对象。单次分析内部预建 PE 节区地址映射，复用最近一次函数解码、字符串引用与调用图查询结果，分析结束后释放。这些缓存不构成行为批准，也不替代构建、规则及验收收据校验。

状态检查先核对完整引擎摘要、规则摘要和全部必要验收场景。已有有效批准时直接报告兼容，不再重新反汇编同一构建；没有有效批准才做结构发现。写入阶段继续生成补丁并核对原字节，官方组件与发布收据仍逐项检查。冷结构发现先以轻量反汇编筛选 RIP 引用，再对命中函数完整解码；相对调用按映射区和 64 KiB 块筛选位移高字，保留重叠指令候选、块边界、取地址和尾跳转检查，最终仍由完整解码证明。

固定等待保留原来的立即数生成方式。随机扰动在同一个已证明的外层策略空间内生成：用时间戳计数器混合得到非密码学随机值，选择闭区间内的整数毫秒，再换算为秒与纳秒返回。只使用易失寄存器，不新增栈、共享状态、外部调用或线程；跨秒和零边界均由执行测试及真实引擎验收覆盖。老设置缺少 `jitter_ms` 时仍表示固定等待，零扰动按旧格式保存；不支持的旧精确结构明确拒绝非零扰动。

目标是让有限的模型外层逻辑拥有重试预算及固定或随机等待，避免内部重试叠加或无预算特例；普通 429 可使用该预算，明确配额耗尽仍结束，并保留其他错误原有分类。写入前检查原字节并保存恢复记录，撤销需要匹配记录与文件状态。

这仍依赖 Windows x64 ABI、PE 函数边界、Rust Duration 表示和支持的指令/控制流形态。协议端点指针与长度目前也要求相邻存储；编译器改用寄存器传参、动态拼接或不同指令调度时可能需要新规则。去掉名称依赖能减少纯重命名造成的失效，不能消除二进制补丁对内部实现的依赖。因此“结构识别失败即拒绝”和“每构建行为验收”仍是必要边界。

## 可选 HTTP 阶段期限

原生 SSE idle timer 在成功的完整 HTTP 响应头返回后才开始，因此不能限制上传、等待响应头或读取未完成错误正文。超时能力放在独立 HTTP 层，避免修改 reqwest 私有结构。开启后 `CODEX_CLI_PATH` 指向副本中的 `codex-guard.exe`，其子进程链为 Python runner → 同目录原生 `codex.exe`。关闭时沿用原来的直接引擎入口。

小入口先以挂起状态创建 runner，加入仅属于它的 Windows Job Object 后继续运行。Job 使用 `KILL_ON_JOB_CLOSE`；入口退出或崩溃会回收自己的 runner、引擎、工具子进程和连接。正常 stdin EOF 先让引擎退出，超时才结束自己创建的子进程。引擎先退出时桥接也结束，不要求桌面再发消息；读取桌面 stdin 使用无缓冲流，避免后台读取锁妨碍 Python 退出。

桌面启动策略读取另走一次性 `app-server --print-startup-config --startup-client-info <JSON>`，退出登录增加 `--startup-sign-out`。这类调用在原生引擎中完成，不进入聊天 JSONL 桥接，也不改写策略结果。runner 按参数边界识别这种模式，显式传递 stdin/stdout/stderr，保留 Windows 无窗口启动下的输出管道。模型请求的 300 秒期限不适用于这条启动策略命令。

runner 通过 stdio 桥接 `thread/start`、`thread/resume` 和 `thread/fork`，先用私有 `config/read` 让引擎解析相应 cwd 的有效配置，再只给该会话覆盖供应商 `base_url`。缺少 cwd 的恢复／分叉先读取 thread 元数据。真实配置文件和公开 `config/read` 结果不修改；私有 RPC 及迟到回复不交给桌面。其他 RPC、工具审批与通知原样通过，等待配置时也不会堵住另一个会话的取消消息。覆盖同时支持独立点分字段与嵌套表；同一字段存在有歧义的两种写法时拒绝猜测覆盖顺序。

转发服务只监听 `127.0.0.1` 的随机端口，通过随机能力路径映射事先注册的上游地址，不接受任意转发目标。请求原始字节在单次阶段期限内接收后发送，可按 HTTP 重定向语义重放；重定向仍在转发层内完成，跨源时由 HTTPX 移除 Authorization。它不对失败请求执行自己的重试。阶段如下：

| 阶段 | 到期行为 |
|---|---|
| 上传、DNS、连接、TLS、重定向、等完整响应头 | 总共一个配置期限；半截或滴答响应头不会重置期限；到期返回 504 |
| 非 SSE 正文，包括错误正文 | 响应头完成后单独开始一个配置期限；成功读取后保留原始压缩字节和端到端响应头 |
| 成功 SSE | 不设总期限，逐块透传；空闲中断仍由引擎 `stream_idle_timeout_ms` 控制 |
| 客户端取消 | 只取消对应的上游操作，不取消其他会话 |

普通连接错误返回 502。普通 4xx 已知但正文不完整时保留状态，408 / 429 超时转成 504；是否重试这些状态继续由原生分类器决定。生成的诊断只有阶段、事件和耗时，不记录认证头、URL、提示词或正文。上游使用系统 TLS 根和标准代理环境，追加 Codex 指定 CA（`CODEX_CA_CERTIFICATE` 优先于 `SSL_CERT_FILE`）；只给引擎子进程追加 loopback 的 `NO_PROXY`，不改父环境或用户配置。企业 PAC / 集成代理认证等组合未专项验收。

上游 HTTPS 实际由 Python/OpenSSL 和 HTTPX 处理，当前使用 HTTP/1.1；不会沿用原生引擎的 Rustls / Schannel 客户端。计时器包围请求阶段，不依赖某个 TLS 实现的内部函数。httpcore 1.0.9 在握手中收到 `CancelledError` 时可能遗漏未入池的 TCP 流；转发层通过公开的 `trace` 扩展取得当前连接，在 TLS 取消事件中显式关闭它，包含 HTTP 代理 CONNECT 后的握手。只处理该请求的连接，不修改全局依赖或生产证书环境。每次 HTTP 验收都必须实测这两种握手超时以及进程退出前的连接回收；依赖变化后不能仅凭返回 504 认定适配成功。

已支持的是显式 `base_url`、Responses HTTP/SSE 和正常 API 认证。WebSocket、AWS 签名认证、无显式 URL 的内置供应商、对话级 profile 切换、按 rollout 路径／原始 history 恢复及非 stdio app-server 明确拒绝。普通帮助、版本、schema 生成及其他 CLI 工具调用直接转交引擎；模型超时保护的验收范围仍为桌面 app-server。未来协议改动需要重新验收，不能据 HTTP 层独立于内部布局就承诺无限兼容。

旧参数缺少 `http_timeout_ms` 表示关闭，显式 0 也按旧格式保存；`retry_enabled` 缺省为 true，仅 false 时写入，保持原有重试参数兼容。期限允许 1000～600000 ms。关闭自定义重试恢复原生策略，和启用自定义但将次数设为 0 有不同含义。

新发布采用 format 5，分开记录期望设置、实际基础引擎和可选超时层：

| 记录 | 内容与失效范围 |
|---|---|
| `requested_profile`、指针的 `last_profile` | 用户期望的完整设置；部分失败时仍保留 |
| `manifest.profile`、`validation.json` | 基础引擎的实际参数、原生收据与沙盒对照，不包含 HTTP 参数或依赖 |
| `http_timeout`、`http-validation.json` | 期限、HTTP 规则与组件摘要、Python/依赖身份、Node 启动对照、包装入口参数/沙盒对照、协议和生命周期验收 |
| `feature_errors` | 未通过的功能及原因，用于逐项状态和待适配提示 |

基础 `desktop_rules_sha256` 不包含 `transport_*` 或 HTTP 依赖清单；超时层有独立的 `rules_sha256`。启动时先验证基础，再验证可选层。HTTP 规则变化、组件/收据损坏、依赖缺失甚至模块无法导入时，禁用超时入口并继续选择已经独立验收的重试引擎。基础收据失效或官方构建变化则仍须重新验收，不能拿另一份收据代替。旧 format 2/3/4 保留各自校验规则，不将旧的合并收据当作新格式的独立批准。

原生适配或参数检查失败时，如果还请求了超时功能，先重新复制官方引擎并核对 SHA，再验证仅超时入口；manifest 中原生 recipe 为 null、重试范围为空、所有引擎组件摘要与官方一致。部分补丁写入不能进入这个模式。两项请求功能都失败时不修改指针；至少一项通过时发布实际可用功能，`degraded=true` 并附 warnings、逐项 features、requested/effective profile。状态中的 `compatible`/`verified` 可表示已有可用入口，原生单项结果另放 `retry_compatible`/`retry_verified`，具体以 features 为准。

失效项在自动启动时沿用保存参数重新尝试；相同构建、规则、依赖和参数失败冷却 6 小时，手动部分成功也记录冷却。手动保存/重新验证可立即尝试，HTTP 规则或依赖变化会打破冷却。提示框在操作锁释放后显示。主动选择官方或关闭两项功能后不会自行重新启用。该隔离不提供运行中桥接崩溃时的无缝接管，也不能撤销上游已经接收的计算；请求重试仍可能产生重复计算或计费。

## 发布前的验收

1. 开启自定义重试时，完整原生构建验收：固定等待 19 项，支持扰动的结构再增加三项，再增加错误与压缩范围的 32 项，共 54 项；覆盖错误分类、预算、毫秒等待、随机范围与变化、跨秒、服务端等待、流中断、连接恢复、app-server、1000 次预算及撤销。资源提示的原文、遮蔽名称及前缀组合均检查零预算、耗尽和成功，另检查压缩与误匹配拒绝。有效的同构建/同规则缓存可复用；声称支持扰动的批准必须包含全部扰动场景。关闭该项时不要求识别二进制补丁结构。
2. 本次参数验收：通过回环模拟 API 运行真实 app-server，并单独验证两类目标错误、带前缀且名称遮蔽的资源错误及手动、自动、回合结束压缩都读取本次参数。0～2 次预算验证耗尽；更高预算检查前两次重连后模拟成功，避免为百万次参数发出百万个测试请求。
3. 沙盒等价对照：原版和副本共六项 unelevated 场景，核对命令结果、受限令牌、工作区内外写入和代理环境。
4. 开启 HTTP 超时时，先由官方随附 Node 运行 `transport_startup.cjs`，对照官方引擎与包装入口各五项：一次性策略读取、临时账号退出、双向 stdio 握手及回环聊天、版本、帮助。一次性命令使用与桌面相同的 `ignore/pipe/pipe`，核对结构化策略、退出码、认证文件行为和普通输出；聊天使用三路 pipe，验证策略和公开配置未改写。失败立即只拒绝超时层，不等待长期限测试；测试程序参与 HTTP 独立规则摘要。Node 不可用也按超时验收失败处理，不阻止已批准的重试入口。
5. 包装入口随后另跑一份参数/沙盒对照，再增加协议和生命周期验收：同一基础引擎的 500 ms 入口覆盖静默连接、半截头、错误正文、普通 400、长 SSE、SSE 空闲、取消后继续、并发、跨进程恢复／分叉、全局 CLI 参数和会话级供应商覆盖，并核对直连／HTTP 代理后的 TLS 握手超时会在停止测试进程前关闭连接；正式发布入口另外真实等待用户设置的期限。stdin EOF、入口被终止、引擎先退出三种情况下，都检查自有 Python／引擎句柄已退出且上游连接已关闭。只启用超时时，隔离测试配置原生 `stream_max_retries=1`、`request_max_retries=0`，验证通知 `1/1`，不将未开启的用户预算误记为生效；真实用户配置仍由 Codex 自行加载。

原生验收最多使用四个工作线程。相同参数共用一个测试期间不再修改的引擎文件，当前 54 个场景对应十一组参数；各次请求探测仍使用各自的临时 CODEX_HOME、配置和回环端口。全部参数镜像制作及撤销恢复检查先完成，再启动计时探测，避免同进程的大块字节复制或补丁操作占用 Python GIL、延迟回环服务线程，造成毫秒等待误判。镜像由正式应用路径使用的 `build_plan` / `patched_bytes` 生成，写入后及全部探测结束后均核对完整摘要。耗时较长的千次预算场景提前排入队列，保留原请求数、等待断言和超时。

本次参数的六条范围探测也最多四路并发，各自使用独立配置和回环服务器，共用只读的待验收副本。结果按固定顺序收集，任何缺项、错误或工作线程异常均阻止发布；沙盒对照在这些参数检查全部通过后执行。

撤销检查在单独且不运行的文件上，通过真实 `Manager.apply` / `restore` 验证；先核对其产物与同参数测试镜像摘要完全一致，再完成原始摘要恢复、重复恢复、部分写入恢复及拒绝覆盖无关修改。任一任务失败均拒绝批准，取消排队任务并等待运行中的探测结束后清理临时文件；用户取消仍由工作进程的 Windows Job Object 回收整个进程树。并行测试会增加短时磁盘占用：当前引擎的十一份参数镜像、原版及恢复文件合计约 4 GiB，成功或常规失败后自动清理。与此前的临时验收目录一样，进程被强制终止时可能留下 state/.verification 下的目录，需在确认验证任务结束后清理；现有“清空历史副本”不覆盖该目录。

临时目录清理只针对本轮创建、位于指定 `.verification` 下的 `native-*` 目录。Windows 共享占用错误（32/33）允许在总计 15 秒内等待释放后继续清理，避免 Python 3.10 的临时目录错误处理将被占用的 EXE 误当目录、掩盖原始错误。它不重新执行验收、不更改权限、不结束占用进程；其他错误或持续占用仍报错，不能生成行为批准。

配套复制 `codex-code-mode-host.exe`、`codex-command-runner.exe`、`codex-windows-sandbox-setup.exe` 和 `rg.exe`，避免跨版本混用。发布前再次核对官方安装、组件、规则和报告，最后原子更新指针。上述过程使用临时配置、回环服务和虚构凭据，不依靠真实模型账号限流来验收。

沙盒对照中的未修改官方引擎与补丁副本都作为独立 override 进程启动，使用相同的 `windows_sandbox_service=true` 功能参数和临时 unelevated 配置。两个测试进程都清除从宿主继承的 `CODEX_WINDOWS_REGISTERED_CORE`、`CODEX_WINDOWS_SANDBOX_PACKAGE_FAMILY`；普通 `Popen` 不因 EXE 位于 WindowsApps 就获得 MSIX 包身份。当前桌面对自定义引擎也清除这两个标记。报告以 `standalone-override` 标明对照环境；六项结果继续逐项核对，但不将它们描述为已注册应用或服务式沙盒等价验收。

临时验收配置关闭插件功能，避免每个新测试进程同步外部插件目录。该配置只属于测试进程，不复制到正式运行副本或真实 CODEX_HOME；HTTP/SSE 重试、原版错误分类、参数和沙盒对照继续实测。HTTP/SSE 探测进程还显式设置 `RUST_LOG=warn`，确保命令行与桌面启动器都能采集原生等待日志；不改父进程、真实配置或正式桌面进程的日志级别。采样随机参数验收同时核对引擎记录的所选毫秒数和实际请求间隔；本地压缩没有该等待日志，使用实际间隔范围及变化验证，并由独立子进程执行测试检查同一等待生成器的毫秒范围。

## 两种更新

官方桌面更新由自定义启动器检测。引擎、桌面构建、配套组件或规则变化都可能要求新副本验收；桌面界面单独更新也会重新绑定构建。相同引擎和规则的完整批准缓存可复用，但不跳过本次发布所需检查。

自动失败按构建、规则、依赖与参数冷却 6 小时；身份变化后可再次尝试，手动保存/验证可立即重试。部分成功会发布可用项并保留期望设置；全部失败不覆盖原指针和旧设置，已选官方默认则不会被自动重新启用。

控制器源码更新由用户 `git pull` 完成，程序没有 GitHub 自动下载器。核心规则和验收程序参与摘要，更新后旧收据可能失效，需要重新验证。

## 存储、锁和进程

自动清理保留指针选中的副本与一代历史，运行中的引擎和配套进程额外保护；手动“清空历史副本”不额外保留历史。恢复官方后保留最后选中的一代。删除前核对目录边界、重解析点、指针和进程，先归档关键 JSON 收据；无法确认归属时跳过或停止，不结束运行进程。

保存、发布、清理与启动选择共享操作锁。锁文件保留不代表锁仍被持有；恢复必须实际尝试获取锁，不能删除文件绕过锁。提示框在释放锁之后显示。

后台工作进程及其测试子进程由 Windows Job Object 管理，取消、超时或父控制器退出时回收本项目任务。手动恢复先核对脚本/管理目录，再用进程句柄核对 PID、路径和创建时间，保护 Codex 桌面和聊天引擎。清理任务完成不等于未完成的参数已发布。

任务栏辅助进程是另一条独立路径，仅维护自定义启动的窗口身份和固定图标，详见[快捷方式说明](SHORTCUTS.md)。
