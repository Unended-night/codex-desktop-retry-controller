# 使用维护与贡献要求

## 更新控制器

1. 等待保存、验证、清理任务结束，关闭控制器窗口，避免源码更新与验收并发。
2. 在项目目录执行 `git status`，保留自己的源码修改；不要用覆盖命令丢弃本地工作。
3. 执行 `git pull`；依赖变化时用同一 Python 执行 `python -m pip install -r requirements.txt`。
4. 重开控制器，先查看 `status` 和[兼容性说明](COMPATIBILITY.md)。规则发生变化后重新验收；已启用入口也会在下次启动时尝试适配。
5. 正常退出后从自定义入口启动，核对“当前运行”。当前引擎不兼容时继续使用官方入口。

`runtime/`、`state/`、`logs/` 和本机图标被 Git 忽略，普通源码更新不会下载或提供这些文件。跨机器安装应重新生成副本和快捷方式，不迁移旧收据来跳过验收。

## 状态、日志与清理

| 本机路径 | 用途 |
|---|---|
| `state/desktop-trial.json` | 启动指针、启用状态和最后保存参数 |
| `state/compatibility/` | 按二进制与规则绑定的完整行为批准 |
| `runtime/*/manifest.json`、`validation.json` | 副本组件清单与验收收据 |
| `runtime/*/controller-state/` | 该副本的撤销记录 |
| `logs/desktop-jobs/` | 保存/验证后台任务结果及日志 |
| `logs/desktop-launch-*.json` | 启动选择与进程观察 |
| `logs/automatic-update.json` | 自动适配与冷却结果 |
| `logs/storage-receipts/` | 删除历史目录前归档的关键收据 |
| `logs/process-recovery.json` | 进程恢复目标、结果与锁检查 |

自动保留当前及一代历史，运行中副本额外保护。需要释放空间先用 `desktop_runtime.py cleanup --dry-run` 查看，再使用界面清理。不要手工删除当前指针需要的目录；不要清空整个项目目录来解决锁问题。

分享问题时优先提供版本、通用错误和脱敏后的摘要。原始日志和收据可能包含路径、命令、环境或本机安装信息，不直接批量上传；真实 `.codex` 配置、认证、会话和数据库不进入仓库。

## 修改代码的约束

- 先读架构、测试与兼容性说明。优先按指令语义、字段、函数边界和分支关系适配，避免只加版本、偏移或分类位图白名单。
- 不修改真实配置、正式安装或运行中的旧副本，不通过终止 Codex 来完成适配，不绕过行为验收。
- 不兼容或验收失败保留参数和旧指针，并允许官方启动；保留失败冷却、手动重试、显式官方默认和只读检查的边界。
- 保留旧补丁与撤销记录兼容性；锁、清理、Job Object 和 PID/创建时间核对不可省略。提示窗口必须在释放操作锁后显示。
- 自定义快捷方式使用稳定本地图标及既有 AppUserModelID，控制器保留自身图标；不要修改官方应用注册或接管无关窗口。
- 图标、快捷方式、恢复报告及状态中可能包含绝对路径，继续留在本机。

## 修改后的验证

先运行[单元回归](../tests/README.md)。若更改原生结构或补丁规则，必须在临时副本、临时配置和回环假 API 下重新运行完整 18 项原生验收；发布副本前再验证实际参数与六项原版/副本沙盒对照。测试后核对正式安装、真实配置和原运行副本摘要保持不变。

`controller.verification.recipe_id()` 绑定控制器源码及原生探测脚本；`desktop_validation.rules_id()` 绑定桌面管理和验证代码。即使只改注释或换行也可能使批准失效，不手工改摘要或拷贝旧批准来规避重新验收。

报告中分别写清单元回归、真实引擎行为、沙盒对照和桌面实际选中副本的结果。无法通过当前构建时应明确记录失败阶段，不将历史版本或单元测试结果包装成最新版已支持。
