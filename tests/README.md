# 测试与验收

## 日常单元回归

Windows x64、Python 3.10+、tkinter 及 `requirements.txt` 中的依赖准备好后，在项目根目录执行：

```powershell
python -B -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

本套件覆盖参数和恢复、规则与收据变化、独立发布失败保留指针、配置提示边界、自动适配和冷却、历史清理、任务栏入口、Job Object、进程恢复和锁释放。测试数量与当次实测结果见兼容性说明。原生识别测试另覆盖枚举与寄存器变化、字段关系、分类标志来源、寄存器别名破坏、分支进入补丁内部、Responses 调用范围和 PE 节区地址映射；有意破坏这些关系时应拒绝适配。结构缓存还验证相同字节复用、返回结果隔离、同长度文件变化重新分析及失败后重试。

`test_native_return.py` 和 `returned-retry.json` 覆盖新版原生返回值规则：三份采样循环、字节标签跳转表及其 Debug String 字段、压缩通过同一分类器返回 Duration 的结构。十五项回归验证地址迁移、枚举重排、字段漂移、短字段加载、易失状态寄存器从同一栈槽恢复，以及错误来源、None 编码、计数和分支不一致时拒绝适配。新增夹具只反汇编，不执行。`test_error_policy.py` 的保护页子进程另执行控制器生成的返回值辅助函数，核对终止/重试结果以及返回给原 JE/JNE 的 ZF 标志，逐字节截断与非法 String 指针检查覆盖新旧两条路径。

`test_native_delegate.py` 与 `delegated-retry.json` 覆盖种类分类器与 Duration 策略拆分、四处采样及三处压缩。除地址／枚举／字段变化外，还验证预算指针帧槽、必须重放的非易失错误指针、短比较的两条 JMP 出口，以及调用后保留的非易失帧加载。已定位的采样或压缩实例证明失败时，另一处有效实例不能掩盖漏补。夹具仅保存所需指令与跳转表，不执行；保护页子进程同时实际执行生成的 CALL 与 JMP 两种叶策略。

`test_transport_guard.py` 使用真实回环 HTTP 连接测试上传、响应头与正文期限、滴答头、长 SSE、取消和并发，核对原始压缩字节、认证与查询参数，并验证重定向仍受期限约束、跨源 Authorization 不泄漏。`test_transport_bridge.py` 运行真正的双向行桥接，检查私有配置回复不泄漏、迟到回复被吞掉、等待配置时取消不被阻塞、未知 RPC 字节保留，以及不支持传输时明确拒绝。`test_transport_runtime.py` 及桌面发布回归检查独立开关、format 5 双收据、HTTP 源码变化不影响基础摘要、缺失依赖／组件／模块只禁用超时、部分原生写入必须恢复官方字节、双失败保留指针、部分成功保留期望参数、自动/手动部分成功冷却，以及 worker/CLI 的仅超时模式。`verify_ui.py` 验证独立控件、期限手动输入、待适配提示和禁用的无效重试输入不阻止仅超时保存。

外部传入采样预算的回归覆盖多个同源循环、字段取址调度、原恢复块保留、预算与计数字段重叠、错误参数错槽和不同通知函数的拒绝。预算写入代码对全部七个允许的状态寄存器、正负字段位移、0 / 300 / 1,000,000 次参数进行反汇编核对。错误布局另覆盖特殊分支之后加载 niche 常量、寄存器重分配、丢失标签来源的拒绝及可打印相邻文本；压缩回归覆盖同一栈槽恢复到另一寄存器，以及错槽和部分寄存器写入的拒绝。

性能回归验证有效批准下状态与验证入口不重复反汇编，同长度文件变化或规则变化必须重新分析；相对引用筛选与完整扫描对照，覆盖跨块、跨节区和位移边界。时间回归覆盖秒／毫秒等价、对称范围、旧配置、扰动收据与保存后的参数；`test_timing.py` 在独立 Windows 子进程中仅执行控制器生成的短时间计算片段，检查整秒、毫秒、跨秒及最大范围，防止除法溢出。它不执行变造的官方引擎。界面切换与范围预览另由 `verify_ui.py` 检查。

`test_native_scope.py` 与 `retry-scope.json` 检查错误标签、String 字段和压缩计数器的推导与漂移，并用逐字节穷举对照一次性名称引用扫描，覆盖重叠、跨块和执行节边界；`test_error_policy.py` 在独立 Windows 子进程中将字符串紧贴不可访问页，检查精准匹配、每一处截断和非目标枚举，防止越界读取。资源错误覆盖实际报告中的前缀与 `***` 组合、未知前缀、近似名称、错误尾句及转义字符串中的伪字段；该实际变体在修复前会失败。`test_core_extension.py` 检查追加中断、扩缩参数、精确截断恢复和无关修改拒绝。参数验收另通过线程屏障验证最多四路实际并发、结果完整有序，以及工作线程失败时拒绝继续发布。

`test_native_suite.py` 验证四线程上限、同参数镜像复用、完整场景与恢复检查、写入损坏拒绝，以及任务失败后等待工作线程退出且不生成批准。全部镜像与恢复检查必须先于计时探测完成；恢复失败不能启动计时探测或生成批准，避免大体积字节操作干扰毫秒计时。清理另覆盖真实 Windows 文件共享锁释放、持续占用超时、其他权限错误原样抛出，以及越界目录拒绝。`test_probe_environment.py` 覆盖父进程未设置日志级别、`off`、`error` 的情况，两个探测入口都须显式采集 WARN 等待日志，且保持父进程环境不变。

Duration 回归覆盖从调用方推导无等待编码、两种比较宽度和分支方向、分类器与调用方编码不一致的拒绝，以及清理块排在连接与预算之间时保持原字节。另验证被跳过的错误指针加载须来自分类器参数的同一栈槽，重放加载后跳入原预算路径；栈槽错配或寄存器别名破坏应拒绝。HTTP 回归同时覆盖有符号和无符号归一化，错误条件方向、标志破坏或状态错配仍应拒绝；完整定位夹具也使用这两种分类形态。

完整定位夹具不含日志、遥测或函数名，覆盖 HTTP 枚举数值及立即数宽度变化、多处 Responses 预算门和零至四层包装。负向场景包括错误端点长度/字段、纯文字引用、未证明的共享调用者、脱节包装、循环、超深和外层候选不唯一；另一处有效候选不能掩盖这些问题。

HTTP 状态来源回归覆盖分类时复用状态寄存器、同一 RBP/RSP 栈槽恢复到不同寄存器、完整寄存器复制，以及地址与字段漂移。错误栈槽、部分或重叠写入、栈基址破坏、地址逸出、分支绕过恢复、跨调用易失状态丢失和调用暂存区来源均应拒绝；完整定位夹具同时保留稳定与恢复状态的两条 HTTP 路径，验证两处预算门都进入补丁计划。

部分测试使用临时目录中的真实 Windows 字节锁、Shell 快捷方式和自己创建的子进程，因此不是跨平台纯逻辑测试。它们不修改真实开始菜单、不接管真实桌面窗口、不结束真实 Codex 或无关用户进程。快捷方式图标在临时目录生成，不依赖本机官方素材；原生指令夹具仅反汇编，不执行变造程序。

清理入口的保留策略测试在当前测试进程执行实际 worker 入口，使模拟进程列表同时用于预览和删除；父进程的 mock 不会自动传入真实子进程。Job Object、工作进程取消和锁冲突仍由其他真实子进程测试覆盖，正式清理遇到不可读进程路径仍拒绝删除。

**单元测试通过不表示当前官方引擎兼容。** 当前发布状态见[兼容性说明](../docs/COMPATIBILITY.md)，本轮环境、结果及 venv 测试波动见[首次发布检查](../docs/PUBLICATION.md)。

## 真实引擎验收

正常用户通过控制器“保存到启动入口”或“重新验证已存设置”触发完整检查，或使用：

```powershell
python -B -X utf8 desktop_runtime.py apply --retries 2 --interval 0.25
python -B -X utf8 desktop_runtime.py apply --retries 300 --interval-ms 1500 --jitter-ms 500 --http-timeout-ms 300000
python -B -X utf8 desktop_runtime.py apply --no-custom-retry --http-timeout-ms 120000
python -B -X utf8 desktop_runtime.py verify
```

这些命令会在全部或部分成功后更新本机下次启动的选择，不是只读测试。`verify` 使用最后保存参数，要求已存在保存设置。重试功能需要当前构建可识别；仅超时模式不要求原生补丁结构兼容，但仍须配套组件完整、可运行 Windows unelevated 沙盒和全部 HTTP 验收。各构建的实际验收状态见[兼容性说明](../docs/COMPATIBILITY.md)。

完整构建套件有 19 项固定等待场景：原有 HTTP 错误与配额终止、固定间隔、Retry-After、服务端建议、SSE、连接恢复、app-server、1000 次预算、对照原版 400 / 401 / 403 / 404 分类，以及新增的 1 毫秒等待。支持扰动的结构另跑 HTTP 随机等待、跨秒和小毫秒范围三项，再增加精准错误和压缩的 32 项，共 54 项；撤销恢复在计时探测前完成。新增场景检查两类 400 的零预算、耗尽与成功，包括资源错误的原文、遮蔽名称和包装前缀组合，普通 bad response/伪 code 的终止，以及手动、自动、回合结束压缩的预算、超过五次、恢复和随机等待。有效批准可缓存，但新构建或规则需要重新批准。

发布还验证本次参数：小预算跑到耗尽，大预算抽样两次重连后成功；两类目标错误、带前缀且名称遮蔽的资源错误及手动、自动、回合结束压缩以最多四路并发分别验证保存参数，缺项或回到 5 次的收据不得发布；另比较原版/副本的六个 unelevated 沙盒场景。模型请求均使用本机回环假 API、虚构密钥和临时 CODEX_HOME，不依赖真实服务账号。

开启 HTTP 期限时，首先由官方随附 Node 执行 `transport_startup.cjs`：官方和包装入口各跑策略读取、临时账号退出、stdio 握手及回环聊天、版本、帮助，共十项。策略命令使用 `ignore/pipe/pipe`，聊天使用三路 pipe；比较官方策略与普通输出，确认空输出、非零退出、缺项或聊天失败不能通过。测试只创建新的临时 CODEX_HOME，不启动真实桌面。Node 缺失或这一步失败立即禁用超时层，已经批准的重试仍可发布。参数路由单元回归同时区分一次性开关与同名参数值。

启动对照通过后，用真正的包装入口另跑参数/沙盒对照，`transport_validation.py` 再跑十一项 500 ms HTTP 场景、两项 TLS 握手、正式入口的实际用户期限，以及 stdin EOF／入口终止／引擎先退出三项进程与连接回收检查。TLS 测试分别直接接收 ClientHello 和通过回环 HTTP 代理接收 CONNECT 后的 ClientHello，保持握手无响应；要求超时通知及上游断开均在停止测试引擎之前发生，不能以退出进程冒充单次取消回收。单元测试另覆盖握手期间用户取消，两种网络路径均须关闭连接。正式期限设置为 300 秒就会实际等待约五分钟，不用短期限测试冒充。短期限入口只对待验收引擎与配套文件建立不写入的硬链接，测试结束后删除；正式入口、Python 依赖和全部回执共同绑定。缺项时不能启用超时层，已经独立通过的重试入口可继续发布。

仅超时验收使用未改动的官方引擎，临时配置的原生预算为 `stream_max_retries=1`、`request_max_retries=0`，期待 `1/1` 通知；用户已保存但未启用的 300 次等自定义值不得进入实际效果断言。真实用户配置不改写。适配失败隔离实验只注入某一适配阶段的失败，剩余参数、沙盒、HTTP 和生命周期检查均运行真实引擎；实验使用独立管理目录，不改真实启动指针。

测试配置设置 `features.plugins=false`，避免插件目录同步成为网络等待瓶颈，不改变用户插件设置。HTTP/SSE 子进程固定 `RUST_LOG=warn`，防止桌面启动器缺少日志环境时误判随机参数失败。采样随机范围由原生等待日志核对；压缩没有该日志，检查实际间隔范围及变化，并配合原生等待生成器的独立执行测试。实测间隔允许调度与网络开销；1 毫秒配置不等于 1 毫秒实时调度保证。

原版/副本沙盒对照使用相同的独立 override 启动环境，保留 `windows_sandbox_service=true` 功能参数，但不继承宿主的已注册 Core 或包族标记。单元回归验证两边的标记都被清除、父环境不变；真实六项对照仍检查受限令牌、工作区内外写入和代理行为。它不验证 MSIX 注册身份或服务式沙盒。

原生场景使用最多四个工作线程、十一份按参数复用的镜像，配合单独原版和恢复检查文件，当前构建临时磁盘占用约 4 GiB。请求数、等待范围、恢复及沙盒检查全部保留；新规则或新引擎首次验收仍需运行全套。2026-10-30 的历史 42 项场景完整发布约 2 分 47 秒，此前 22 项版本约 2 分 41 秒；优化前后和计时失败记录见兼容性说明；不要把缓存批准后的保存时间当作首次完整验收耗时。

真实引擎的诊断文字等长改写只用于内存结构回归，必须得到相同补丁计划，变造映像不执行。多个 HTTP 门通过静态范围检查，不等于每个门或所有 feature 组合都已由现有默认 HTTP 行为套件逐一覆盖。

## 手工工具的前提

| 工具 | 说明和限制 |
|---|---|
| `verify_ui.py` | 读取实际安装和状态，创建 UI 检查显示与按钮；不点击真实保存，需可用桌面会话 |
| `verify_desktop_integration.py` | 隔离管理目录，经 pythonw → 后台工作进程验收参数、沙盒和恢复；需已有有效原生批准及已选副本指针 |
| `verify_structure.py` | 检查实际引擎结构，内存变造片段不得执行；使用旧安装定位 |
| `verify_native.py` | 临时副本完整行为与恢复，默认允许有效缓存；使用旧安装定位 |
| `verify_approved_write.py` | 已批准路径的临时副本写入与恢复；使用旧安装定位 |
| `verify_profile.py` | 临时副本 15 次 / 5 秒及原版分类对照，须有效批准，可能耗时超过一分钟；使用旧安装定位 |
| `verify_reported_rate_limit.py` | 回环 SSE 模拟固定限流文字，核对通知、请求数和间隔；须有效批准，使用旧安装定位 |

旧定位指 `%LOCALAPPDATA%/OpenAI/Codex/bin` 布局，可能无法找到当前 WindowsApps 桌面包；不要把这些脚本全部列为新安装后一键成功的命令。主控制器使用当前用户注册表定位，不受这项旧脚本入口限制。

`research/verify_desktop_runtime.py` 的可复用函数参与正式发布验收，但其独立 `main()` 仍有历史构建路径，不应直接当成通用入口。
