# 测试与验收

## 日常单元回归

Windows x64、Python 3.10+、tkinter 及 `requirements.txt` 中的依赖准备好后，在项目根目录执行：

```powershell
python -B -X utf8 -m unittest discover -s tests -p "test_*.py" -v
```

本套件包含 136 项测试，覆盖参数和恢复、规则与收据变化、独立发布失败保留指针、配置提示边界、自动适配和冷却、历史清理、任务栏入口、Job Object、进程恢复和锁释放。原生识别测试另覆盖枚举与寄存器变化、字段关系、分类标志来源、寄存器别名破坏、分支进入补丁内部、Responses 调用范围和 PE 节区地址映射；有意破坏这些关系时应拒绝适配。结构缓存还验证相同字节复用、返回结果隔离、同长度文件变化重新分析及失败后重试。

Duration 回归覆盖从调用方推导无等待编码、两种比较宽度和分支方向、分类器与调用方编码不一致的拒绝，以及清理块排在连接与预算之间时保持原字节。另验证被跳过的错误指针加载须来自分类器参数的同一栈槽，重放加载后跳入原预算路径；栈槽错配或寄存器别名破坏应拒绝。HTTP 回归同时覆盖有符号和无符号归一化，错误条件方向、标志破坏或状态错配仍应拒绝；完整定位夹具也使用这两种分类形态。

完整定位夹具不含日志、遥测或函数名，覆盖 HTTP 枚举数值及立即数宽度变化、多处 Responses 预算门和零至四层包装。负向场景包括错误端点长度/字段、纯文字引用、未证明的共享调用者、脱节包装、循环、超深和外层候选不唯一；另一处有效候选不能掩盖这些问题。

部分测试使用临时目录中的真实 Windows 字节锁、Shell 快捷方式和自己创建的子进程，因此不是跨平台纯逻辑测试。它们不修改真实开始菜单、不接管真实桌面窗口、不结束真实 Codex 或无关用户进程。快捷方式图标在临时目录生成，不依赖本机官方素材；原生指令夹具仅反汇编，不执行变造程序。

清理入口的保留策略测试在当前测试进程执行实际 worker 入口，使模拟进程列表同时用于预览和删除；父进程的 mock 不会自动传入真实子进程。Job Object、工作进程取消和锁冲突仍由其他真实子进程测试覆盖，正式清理遇到不可读进程路径仍拒绝删除。

**单元测试通过不表示当前官方引擎兼容。** 当前发布状态见[兼容性说明](../docs/COMPATIBILITY.md)，本轮环境、结果及 venv 测试波动见[首次发布检查](../docs/PUBLICATION.md)。

## 真实引擎验收

正常用户通过控制器“保存到启动入口”或“重新验证已存设置”触发完整检查，或使用：

```powershell
python -B -X utf8 desktop_runtime.py apply --retries 2 --interval 0.25
python -B -X utf8 desktop_runtime.py verify
```

这些命令会在成功后更新本机下次启动的选择，不是只读测试。`verify` 使用最后保存参数，要求已存在保存设置。需要当前构建可识别、配套组件完整、可运行 Windows unelevated 沙盒且有足够临时空间。各构建的实际验收状态见[兼容性说明](../docs/COMPATIBILITY.md)。

完整构建套件有 18 项：HTTP 错误与配额终止、固定间隔、Retry-After、服务端建议、SSE、连接恢复、app-server、1000 次预算、恢复原字节，以及对照原版 400 / 401 / 403 / 404 分类。有效批准可缓存，但新构建或规则需要重新批准。

发布还验证本次参数：小预算跑到耗尽，大预算抽样两次重连后成功；另比较原版/副本的六个 unelevated 沙盒场景。模型请求均使用本机回环假 API、虚构密钥和临时 CODEX_HOME，不依赖真实服务账号。

真实引擎的诊断文字等长改写只用于内存结构回归，必须得到相同补丁计划，变造映像不执行。多个 HTTP 门通过静态范围检查，不等于每个门或所有 feature 组合都已由现有默认 HTTP 行为套件逐一覆盖。

## 手工工具的前提

| 工具 | 说明和限制 |
|---|---|
| `verify_ui.py` | 读取实际安装和状态，创建 UI 检查显示与按钮；不点击真实保存，需可用桌面会话 |
| `verify_desktop_integration.py` | 隔离管理目录，经 pythonw → 后台工作进程验收参数、沙盒和恢复；需已有有效原生批准及已选副本指针 |
| `verify_structure.py` | 检查实际引擎结构，内存变造片段不得执行；使用旧安装定位 |
| `verify_native.py` | 临时副本完整行为与恢复，默认允许有效缓存；使用旧安装定位 |
| `verify_approved_write.py` | 已批准路径的临时副本写入与恢复；使用旧安装定位 |
| `verify_profile.py` | 临时副本 15 次 / 5 秒及原版分类对照，须有效批准，可能耗时超过一分钟；使用旧安装定位 |
| `verify_reported_rate_limit.py` | 回环 SSE 模拟固定限流文字，核对通知、请求数和间隔；须有效批准，使用旧安装定位 |

旧定位指 `%LOCALAPPDATA%/OpenAI/Codex/bin` 布局，可能无法找到当前 WindowsApps 桌面包；不要把这些脚本全部列为新安装后一键成功的命令。主控制器使用当前用户注册表定位，不受这项旧脚本入口限制。

`research/verify_desktop_runtime.py` 的可复用函数参与正式发布验收，但其独立 `main()` 仍有历史构建路径，不应直接当成通用入口。
