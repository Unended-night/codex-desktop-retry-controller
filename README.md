# Codex Desktop Retry Controller：失败尝试归档

为 Windows 上的 Codex 桌面版提供中文控制器：分别开关自定义重试和 HTTP 响应超时，设置次数、毫秒级等待、随机扰动与阶段期限，通过独立、经过验收的引擎副本启动。官方安装与用户配置保持原样。

这是社区工具，与 OpenAI 无隶属关系。仓库只分发控制器源码；使用者需要自行安装官方 Codex 桌面版。

> **最终结论（2026-11-22）：本次 HTTP 超时入口方案失败，已按用户要求放弃。** 实际桌面无法继续聊天，弹出“HTTP 超时层尚未验收按路径或原始历史恢复”，用户另报告模型列表不显示。此前隔离测试没有覆盖实际使用路径，不能证明入口可用。本分支只保存失败源码、测试和[失败记录](docs/FAILED-ATTEMPT-2026-11-22.md)，不应继续部署。下文保留的是尝试过程中的设计和操作说明；本机将清除超时配置和构建副本，回到 `main` 恢复仅重试控制器。

## 能做什么

- 最多重试 **0～1,000,000 次**，不含首次请求；0 表示不重试。
- 等待支持 **秒／毫秒**切换，精度为 **1 毫秒**；不含请求本身的耗时。
- 可配置对称随机扰动，例如 **1000 ± 70 毫秒**，每次失败后选择 **930～1070 毫秒**等待；扰动为 0 时保持固定等待，整个范围须在 0～60 秒内。
- 独立开关 **自定义重试**和 **HTTP 响应超时**，可两项同用、只用其中一项，或全部关闭；一项适配失败时仍可发布另一项。
- **HTTP 响应超时**可手动输入 **1～600 秒**（精度 1 毫秒）：请求上传／完整响应头、非流式正文各自超过期限后，交给引擎重试。自定义重试开启时使用已保存的次数与间隔，关闭时使用原生策略。正常 SSE 没有总时长限制，继续使用引擎原有的流空闲超时。
- 独立副本制作、行为验收、启动指针原子切换，以及恢复官方默认。
- 官方桌面更新后沿用保存参数，分别验收所选功能；未适配项保留设置并提示，可用项先发布。
- 自动保留当前副本与一代历史，保护运行中的副本；提供历史清理和控制器进程恢复。
- 管理自定义启动快捷方式的稳定图标与任务栏关联。

原有采样及 HTTP 拆分函数规则按错误分类数据流、预算字段、分支和 Responses 调用关系定位，不依赖内部函数名、遥测名及诊断文字，并支持有限包装链和多个通过范围检查的 HTTP 实现。这些规则支持 HTTP 状态指针经完整寄存器复制或同一未被改写的栈槽恢复，分类过程可复用原状态寄存器；仍核对调用、分支和计数写回关系。这样可减少重命名与有限布局变化带来的失效；ABI 或控制流重构仍可能需要适配，历史精确规则也保留原有约束。新增错误布局使用枚举 Debug 名称、压缩范围补充使用诊断文字锚点，仍须通过指令关系检查；这些锚点变化也可能需要适配。详见[后续版本预期](docs/COMPATIBILITY.md#后续版本的预期)。

作用范围是模型采样的 **HTTP / Responses / SSE** 重试，以及当前构建中通过模型生成摘要的本地压缩（手动、自动和回合结束后的压缩）。两类原本会终止采样的 HTTP 400 也使用同一配置：Azure 资源不匹配的完整提示，以及错误 JSON 的 `code=invalid_encrypted_content`。资源提示支持已观察到的 `OpenAI Responses bad request: ` 前缀，以及 `Azure` 被替换成 `***` 的变体；仍须匹配完整原因和修复说明。其他 400 保留原行为，仅出现 `bad response` 文字不会被新增规则判为可重试。

已有规则支持外部传入预算的多份采样循环、已证明的字段取址调度、错误 Debug 分派的寄存器与常量位置变化，以及压缩状态从同一栈槽重新加载的结构。历史规则继续保留，后续更新仍须重新识别并通过行为验收。

2026-11-15 增加字节标签错误枚举和压缩分类器适配，2026-11-22 进一步支持错误种类与 Duration 策略分离、短比较及分类后帧加载。规则保留原生分类，根据字段和控制流推导仅因缺少服务器等待时间而终止的分支，使用用户等待；明确额度耗尽继续终止。当前构建识别到四处采样循环、三处 HTTP 预算门和三处压缩循环。已定位循环证明失败会拒绝整个适配，避免静默漏补。旧规则继续保留，没有添加版本号、固定偏移、循环数量或枚举编号白名单。

HTTP 超时选项为显式配置 `base_url` 的 Responses HTTP/SSE 供应商补上响应头前的等待期限。旧设置默认关闭；不改写用户 `config.toml`。它通过独立入口和回环转发层生效，转发层不自行重试，避免预算叠加。完整错误响应仍按原生分类处理；不完整错误正文超时会保留已经收到的普通 4xx 状态（408 / 429 除外）。状态是否重试由引擎决定，不能把 401 一概视为永不重试。

内置且无显式地址的供应商、WebSocket、AWS 签名认证、对话级 profile 切换、按路径／原始 history 恢复尚未纳入超时入口验收，遇到这些配置会明确提示关闭 HTTP 超时选项。独立远程压缩、远程主机和所有后台请求也未完整覆盖。它不提高服务端额度，不能当作全局网络重试开关。

## 环境与安装

| 项目 | 要求与边界 |
|---|---|
| 系统 | Windows x64，当前用户已注册安装的官方 Codex 桌面包 |
| Python | 3.10+，64 位，包含 tkinter；同目录需要 `python.exe`，快捷方式建议使用 `pythonw.exe` |
| Python 依赖 | `requirements.txt` 中的 capstone、pefile、httpx、h11；Python 3.10 另安装 tomli |
| 超时入口 | 使用 Windows 自带 .NET Framework C# 编译器构建；启动验收使用官方随附 Node，缺失时只拒绝 HTTP 层；绑定当前 Python 和 HTTP 依赖版本，改变后重新验收 |
| 其他平台 | 未支持 macOS、Linux、WSL、Windows ARM64 或独立终端 CLI |
| 引擎版本 | 每个构建须通过结构识别及行为验收，不能仅凭版本号判断兼容 |
| 磁盘空间 | 一代完整副本通常数百 MB；自动保留两代，首次并行验收当前构建另需约 4 GiB 临时空间 |

从 PowerShell 执行；以下 `python` 应指向同一个 Python 安装或虚拟环境：

```powershell
git clone https://github.com/Unended-night/codex-desktop-retry-controller.git
Set-Location .\codex-desktop-retry-controller
python -m pip install -r requirements.txt
python -m tkinter
python -B -X utf8 desktop_runtime.py status
```

`python -m tkinter` 用于确认界面依赖，关闭测试窗口后继续。缺少 tkinter 时请通过 Python 安装程序补齐；它不是这里的 pip 依赖。程序不自动下载 Python 依赖或官方引擎。

## 使用

1. 运行 `python -B -X utf8 app.pyw`，或双击 **启动控制器.cmd**。后者要求所需的 `pythonw.exe` 已在 PATH 中；有多个 Python 安装时应确认它与安装依赖的解释器一致。本轮完整回归使用直接 Python 解释器，虚拟环境的验证限制见兼容性说明。
2. 查看“当前运行”“下次启动”和两项功能状态，按需要勾选 **自定义重试次数**、**HTTP 响应超时**，填写参数并点击 **保存到启动入口**。例如时间单位选“毫秒”，基础等待填 `1000`、随机扰动填 `70`，界面会预览 `930～1070 毫秒`。切换单位会换算输入值。每项功能分别验收；当前已运行的 Codex 不会被替换。
3. 正常退出 Codex，再点击控制器的 **启动 Codex**，或从下述“自定义重试”快捷方式启动。重新检测以确认实际运行的引擎与参数。
4. **恢复官方默认**让同一启动入口下次使用官方引擎，保留最后保存的参数；不会自动重新启用自定义。
5. **重新验证已存设置**按最后保存的参数重新制作并验收副本，成功后重新启用自定义。输入框里尚未保存的修改不参与。

首次打开控制器只检测。重试结构不兼容时仍可尝试仅启用 HTTP 超时；超时入口不兼容时仍可保存已验收的重试副本。未通过的功能显示“待适配，设置已保留”，不会自动取消勾选。首次保存至少需要一项功能通过；全部失败时保留旧指针和旧设置。

需要处理长时间没有响应的请求时，勾选 **HTTP 响应超时**，例如填 `300` 秒。保存时会真实等待一次该期限，再验证超时与重试，因此比关闭选项时更慢；这不是控制器卡住。两项都开启时，等待响应头超过 300 秒会结束该请求，再按重试次数与等待间隔继续。300 秒是单次阶段期限，不是聊天或全部重试的总期限；工具执行和人工审批不受这个 HTTP 期限控制。

**关闭自定义重试不等于禁止重试**，而是交还 Codex 原生策略。需要禁止重试时，应开启自定义重试并把次数设为 `0`。只开 HTTP 超时时使用字节完全一致的官方引擎。两项都关闭后使用官方入口，未启用的重试参数仍保留。

| 本次验收结果 | 下次启动 |
|---|---|
| 两项都通过 | 自定义重试 + HTTP 超时 |
| 重试通过、超时失败 | 使用重试副本；提示超时未启用，保留期限，提醒重新验证或适配 |
| 重试失败、超时通过 | 官方原版引擎 + HTTP 超时；提示自定义重试未启用 |
| 两项都失败 | 保留旧指针和设置；当前构建没有有效副本时使用官方入口 |

隔离针对适配、验收和启动选择。运行中的超时入口如果崩溃，会回收自己的进程树，不能在同一次聊天中无缝切换到另一种入口。

1 毫秒是参数精度，不代表 Windows 能保证 1 毫秒准时发起请求；系统调度和请求耗时可能使实测间隔更长。等待从失败处理后开始，不是所有成功请求之间的全局限速。随机扰动目前仅在支持的拆分函数结构上启用，旧精确结构继续支持固定等待。

## 两种快捷方式

| 入口 | 目标脚本 | 用途 |
|---|---|---|
| Codex 重试控制器 | `app.pyw` | 打开设置界面 |
| Codex 自定义重试 | `desktop_trial.py` | 检查设置与收据，启动合适的桌面引擎 |
| 官方 Codex | 官方安装入口 | 使用官方引擎 |

**设置界面与真正的启动入口是两个快捷方式。** 创建方法、项目迁移、图标修复与任务栏固定步骤见[快捷方式说明](docs/SHORTCUTS.md)。`.lnk` 含本机绝对路径，因此不随源码分发。

自定义入口使用项目内稳定的 `assets/codex.ico`，缺失或损坏时从当前官方安装提取恢复。官方图标不随公开仓库分发。控制器使用自身原有图标；官方更新和历史副本清理不需要改快捷方式的版本路径。

## 更新与工作原理

启动器从当前用户注册信息定位官方桌面包，通过进程级 `CODEX_CLI_PATH` 选择经过验收的独立引擎副本，不覆写 WindowsApps 中的正式安装。每次启动检查构建、组件、规则与收据；需要新副本时先验收，再原子切换启动指针。

- **官方 Codex 更新**：已启用的自定义入口自动尝试适配并沿用参数；部分成功时发布可用功能并提示缺失项，全部失败时保留旧指针与参数。相同构建、规则、依赖和参数的失败冷却 6 小时，手动部分成功也计入冷却。手动保存或重新验证可立即重试。
- **控制器源码更新**：本项目没有自动下载更新器。在项目目录执行 `git pull`；依赖声明变化时重新安装依赖。基础引擎与 HTTP 层有独立收据和规则摘要；仅 HTTP 源码、组件或依赖变化时，已验收的重试入口仍可使用，超时层需要重新验收。
- **正在运行的 Codex**：保存设置和更新适配不热替换当前进程。正常退出后从自定义入口重新启动。

详细流程见[原理说明](docs/ARCHITECTURE.md)，更新和维护要求见[维护说明](docs/MAINTENANCE.md)。

检测会核对完整文件和规则摘要，已有有效行为批准时省去重复反汇编。2026-10-30 的历史测量中，本机状态检测 **4.0～5.0 秒**，相同参数重复保存（含后台 worker）**2.7～3.3 秒**，均复用已验收副本；当时 42 项场景首次完整验收并发布由 **225 秒**降至 **167 秒**。当前验收将镜像制作、恢复与计时分阶段执行，以减少自身负载干扰；这些历史耗时不代表当前版本的首次验收耗时。新参数仍需制作并验证对应副本；完整测量与波动见[性能记录](docs/COMPATIBILITY.md#本轮性能记录)。

## 常用命令与恢复

在项目根目录执行：

```powershell
python -B -X utf8 desktop_runtime.py status
python -B -X utf8 desktop_trial.py --check
python -B -X utf8 desktop_runtime.py apply --retries 20 --interval 1
python -B -X utf8 desktop_runtime.py apply --retries 20 --interval-ms 1000 --jitter-ms 70
python -B -X utf8 desktop_runtime.py apply --retries 300 --interval-ms 1500 --jitter-ms 500 --http-timeout-ms 300000
python -B -X utf8 desktop_runtime.py apply --no-custom-retry --http-timeout-ms 120000
python -B -X utf8 desktop_runtime.py apply --no-custom-retry --http-timeout-ms 0
python -B -X utf8 desktop_runtime.py verify
python -B -X utf8 desktop_runtime.py restore
python -B -X utf8 desktop_trial.py --official
python -B -X utf8 desktop_runtime.py cleanup --dry-run
python -B -X utf8 desktop_runtime.py recover --dry-run
```

`status` / `--check` 不制作副本、不切换入口、不修复快捷方式；仍可能记录检查日志。`apply` / `verify` 分别验收所选功能。`--no-custom-retry` 可以省略未启用的次数和等待参数，保留最后保存值；`--http-timeout-ms 0` 关闭超时。`cleanup` 去掉 `--dry-run` 后清空可删除历史，保留运行中和下次启动所需的副本；自动清理则额外保留一代历史。

保存或验证卡住时，可用界面的 **清理控制器进程**；按钮在后台任务忙碌时仍可用。它只处理核实属于本项目的启动器、验证任务及子进程，保护真实 Codex 桌面和聊天引擎，并实际检查锁能否重新获取。不要删除锁文件来假装解锁。命令行实际恢复为 `python -B -X utf8 desktop_runtime.py recover`。
